# SSM patch management

Creates an OS patch baseline, separate nonproduction scan/install windows, and an optional production window. `patch_policy = null` uses AWS default OS baselines and creates no custom baseline or patch-group association. `nonproduction.scan_only = true` creates only the Scan window, with no Install schedule or task. `nonproduction.target_instance_ids` applies the required `Environment` and `PatchGroup` tags to explicit EC2 instances. Production installation is scheduled only as an Automation document whose first step is `aws:approve`; denial or timeout aborts before `AWS-RunPatchBaseline` runs. After approval, the runbook checks that the maintenance-window execution is still active and at least five minutes remain before cutoff, then rechecks the instance's production and patch-group tags before starting installation. AWS may let a command already started within a window finish after it closes.

Targets are EC2 instances matching **both** `Environment` and `PatchGroup` tags through an AWS Resource Group. The patch group must be unique per environment. Instances need SSM Agent, an SSM-capable instance profile, and network access to Systems Manager endpoints. The caller supplies Maintenance Window and Automation roles; scope their permissions to the intended resources and tags. The Automation role needs `ssm:GetMaintenanceWindowExecution`, `ssm:GetMaintenanceWindow`, `ec2:DescribeInstances`, and permissions to run `AWS-RunPatchBaseline` on matching instances. Use one module instance per supported OS baseline.

Production is disabled by default (`production = null`). Supplying production configuration creates a schedule, so review the Terraform plan, approver ARNs, SNS topic, tag matches, and role permissions before applying. The approval and Automation execution histories in Systems Manager provide audit evidence. Patch compliance is visible in Patch Manager; failed task and command executions are visible in Systems Manager Maintenance Windows and Run Command.

Before production: run nonproduction Scan and Install, record target IDs and compliance results, verify instance and application health, and rehearse rollback using the prior AMI or launch-template version. Stop on failed commands, unhealthy instances, or failed smoke tests. This module does not create instance profiles, network endpoints, AMIs, monitoring alarms, or perform rollback automatically.

Initialize with `terraform init -backend=false`; then run `terraform validate` and `terraform test` in this directory. See `examples/ssm-patch-management` for inputs.
